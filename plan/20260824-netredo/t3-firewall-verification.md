## 0. Cross-check: DOC matrix vs IaC forward chain (MISMATCH REPORT)

Read `docs/network-vlans.md` §Inter-VLAN Firewall Rules (doc matrix) and the `data:` block of
`roles/router/tasks/main.yml` "Ensure inter-VLAN forward firewall rules". Every clearly stated
matrix rule is implemented. Findings:

### No hard functional mismatch — 3 clarifications / notes

1. **IoT→DNS is explicit in the chain but not a matrix row.** The matrix's "All (except IoT)→WAN
   allowed" + general DNS rows don't list IoT→DNS separately, yet the chain has an explicit
   `IoT → DNS resolver` (vlan20 → dns_primary, udp/tcp 53,853 accept). **Note only** — the chain is
   stricter and correct (IoT→WAN is dropped, DNS is a narrow allowed exception).

2. **`trusted-admin → IoT` / `trusted-admin → IoT-Internet` are `new` allows with NO dst-port
   filter.** The matrix says "Accept established/related + new from trusted IPs (MQTT/HA)". The chain
   matches — but a trusted-admin host can reach ANY port on a VLAN-20/21 device, not just MQTT/HA
   ports. Matches the matrix wording ("new from trusted IPs"); **looser than the "MQTT/HA" hint**.
   Flagged for awareness; not a mismatch. If tight-scope is wanted, add dst-port filters (out of scope
   here — Task 3 is planning only).

3. **`Home → IoT` / `Home → IoT-Internet` are TCP-only `established,related`.** The matrix says
   "Accept established/related" unconditionally; the chain restricts those two rows to `protocol: tcp`.
   UDP established return through those rows is NOT accepted (IoT→DNS has its own row, so DNS is fine).
   **DOC-vs-IaC NOTE (low):** the doc should say "TCP established/related" for Home→IoT/21, or the
   rule should not restrict protocol. No behavior change needed now; documented so the cutover test
   (a UDP established test from Home→vlan20 would FAIL while the doc implies it should pass). Add this
   to a future network-vlans.md edit.

### `trusted-admin` / `trusted-ha` membership (for test IPs)

- `trusted-admin` = oldsrv, nas, ha-vip — **all static-host rows for those names, any VLAN**
  (oldsrv/nas/pi have both 99 and 10 rows, so both addresses join the list).
- `trusted-ha` = oldsrv, ha-vip (NOT nas).
- `ups_management` = ups (10.10.99.9).
- `vps_s2s_peer` / `vps_scoped_home` = WireGuard S2S (not exercised by LAN-local probes; see §1-I).

**Conclusion:** matrix and chain agree on security posture. The 3 notes are clarifications, not gaps.

## 2. Copy-paste-runnable script (cutover window)

```bash
#!/bin/bash
# t3-firewall-cutover-check.sh — read-only firewall-matrix verification (Task 3)
# Run AFTER the RB4011 cutover + forward chain converged. Safe/idempotent, no mutation.
set -uo pipefail
PASS=0; FAIL=0
chk(){ exp="$1"; desc="$2"; shift 2; "$@" >/dev/null 2>&1; rc=$?
 
chk BLOCK "J2 Home->Mgmt 22"          nc -z -w3 10.10.99.2 22
echo
echo "SUMMARY: PASS=$PASS FAIL=$FAIL"
```

> **Important:** rows marked "from vlanXX" (A2, D1-D3, E1-E2, F2, H1-H5, J2) must be run FROM a host
> on the source VLAN (ssh into a device on that VLAN, or connect a probe laptop to that SSID / access
> port). The script covers the mgmt-reachable subset; run the §1 rows per-VLAN for a complete matrix
> proof.

## 3. Bedtime-block verification (time-of-day)

The Kids→WAN bedtime drop uses RouterOS native `time=22:00:00-07:00:00` (stateless, reboot-safe).
At 14:00 H4 passes and H5 cannot be observed. Options:

- **Deferred (recommended):** verify rule presence with
  `/ip firewall filter print where src-address=10.10.40.0/24 and action=drop` → confirm the row has
  `time=22:00:00-07:00:00`. Then run H5 at ~23:00 on cutover night (or a timed background job at
  22:05 that records PASS/BLOCK to a file). No persistent config change.
- **Temporary override (no persistent change):** RouterOS `time=` has no portable "now" flag. To
  force-test without editing the live rule, add a **temporary staging copy** of the bedtime rule with
  the bracket flipped (e.g. `07:00:00-22:00:00`), probe, then **delete** it. This proves the mechanics
  without touching the rendered rule. Do NOT modify the live rule itself.

**No persistent change** in any option; the `time=` rule stays as-rendered.
