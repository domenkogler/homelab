## Architecture Philosophy

- **Database-free, pure GitOps** — all config, versions, and documentation are plain text in Git
- **One Git repo** — IaC code + technical docs + family guides live together in the Forgejo repo
- **Ansible-driven** — deployments, config generation, and documentation updates all flow through Ansible
- **Five non-overlapping interfaces** — each tool has exactly one job (see matrix below)

## Interface Matrix (5 Tiers)

Every interface in the homelab has a strict, non-overlapping responsibility. All are configured from the same repo and auto-generated by Ansible.

## Renovate Bot

Tracks upstream Docker image versions and enforces a stability delay before surfacing updates.

### How It Works
1. Renovate container runs on VPS, scans `docker-compose.yml` files in the repo
2. New upstream Docker image detected → **3-day hold** (stability delay)
3. After 3 days, update appears as a checkbox item on the **Dependency Dashboard** (a Forgejo Issue, auto-managed by Renovate)
4. Domen reviews the update, checks the box
5. Renovate generates a PR with the version bump
6. Merge PR → version string committed to Git → ready for deployment

### Configuration (`renovate.json` at repo root)

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "platform": "forgejo",
  "dependencyDashboard": true,
  "dependencyDashboardAutoclose": false,
  "dependencyDashboardTitle": "Homelab Dependency Dashboard",
  "packageRules": [
    {
      "matchDatasources": ["docker"],
      "stabilityDays": 3
    }
  ]
}
```

> The Dependency Dashboard is a **Forgejo Issue** (not a wiki page). Renovate creates and maintains it automatically. No manual setup beyond the config file.

## Forgejo Actions

The CI/CD runner that executes Ansible playbooks when a deployment is triggered.

### Workflow (`.forgejo/workflows/deploy.yml`)

```yaml
name: Manual Infrastructure Deploy

on:
  workflow_dispatch:
    inputs:
      target_tag:
        description: 'Ansible tag to deploy (e.g., ollama, immich, homepage)'
        required: true
        default: 'all'

jobs:
  ansible-deploy:
    runs-on: docker
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Run Ansible Playbook
        run: |
          ansible-playbook main_deploy.yml --tags "${{ github.event.inputs.target_tag }}"
```

### Runner Prerequisites

The Actions runner container needs:
- **SSH key** (ED25519) — access to all managed nodes
- **1Password CLI** + `OP_SERVICE_ACCOUNT_TOKEN` — secret resolution at deploy time
- **Git push access** — to commit auto-generated docs (inventory, Homepage config) back to the repo
- **Ansible collections** — `community.docker`, `community.general`

### Execution Modes

| Mode | Trigger | Scope | Used For |
|------|---------|-------|----------|
| **Bootstrap** | Domen's laptop: `ansible-playbook site.yml -i inventory.ini` | Full provisioning of new/rebuilt nodes | Initial setup, disaster recovery |
| **Production** | Forgejo Actions: `workflow_dispatch` with `--tags <service>` | Single container update | Day-to-day container updates after Renovate PR merge |

## Homepage (Family Launchpad)

A sleek, family-friendly web dashboard — the everyday landing page for all homelab services.

### Deployment
- **Runs on:** VPS Docker (Services bridge)
- **Exposed at:** `kogler.si` (root domain)
- **Authentication:** Protected by **Authentik Forward Auth** via Traefik middleware. After first SSO login, session cookie persists — zero friction for family
- **Configuration:** `services.yaml` and `widgets.yaml` — auto-generated by Ansible post-deploy hook

### Health Checks
- **VPS services:** Monitored via local Docker socket
- **Home server services:** Monitored via HTTP health endpoints, reachable through site-to-site WireGuard tunnel
- **Status indicators:** Green/red dots on each service tile
- **Local-only links:** Services like Home Assistant (`ha.kogler.lan`) and Technitium (`dns.kogler.lan`) show as links but only resolve on home network or VPN

### Auto-Generation

After Ansible deploys or updates any container, the `docker_services` role's post-deploy hook:
1. Renders `homepage_services.yaml.j2` → writes to `/opt/homepage/config/services.yaml` on VPS
2. Renders `homepage_widgets.yaml.j2` → writes to `/opt/homepage/config/widgets.yaml` on VPS
3. Reloads Homepage container
4. Commits both files to Git (so the repo reflects current state)

## Deployment Lifecycle (End-to-End)

```
Upstream Docker Release
        │
        ▼ (Renovate detects new version)
  3-Day Stability Hold
        │
        ▼
  Renovate posts to Forgejo Issue (Dependency Dashboard)
  □ immich: v1.120.0 → v1.122.1
        │
        ▼ (Domen checks the box)
  Renovate creates PR with version bump
        │
        ▼ (Domen reviews release notes, merges PR)
  Version committed to Git
        │
        ▼ (Domen navigates to Forgejo Actions tab)
  workflow_dispatch: target_tag = "immich"
        │
        ▼ (Actions runner executes Ansible)
  ansible-playbook main_deploy.yml --tags immich
        │
        ▼ (Post-deploy hooks)
  ├─ Regenerate Homepage services.yaml (new version shown)
  ├─ Regenerate inventory docs
  └─ Commit + push updated docs to repo
        │
        ▼
  Homepage reloads → family sees updated status
```

## Obsidian (Admin Knowledge Base)

Domen's desktop tool for offline documentation editing and visual diagramming.

### Setup
- **Obsidian vault** = local clone of the homelab Git repo
- **Targets `docs/` folder** — both technical docs and family guides
- **Canvas feature:** Visual network topology maps, infrastructure diagrams, cluster maps — all stored as `.canvas` files in the repo
- **Edit workflow:** Edit locally in Obsidian → commit → push to Forgejo → rendered in Forgejo file viewer

### Why Obsidian
- Offline editing (no web UI dependency)
- Canvas for visual diagrams (no external drawing tools)
- Bidirectional linking between documents
- Plain Markdown — fully Git-friendly

## Security Boundaries

| Boundary | Detail |
|----------|--------|
| **Actions runner → managed nodes** | Dedicated SSH key (separate from Domen's personal key). Key stored as Forgejo secret |
| **Actions runner → 1Password** | Service Account token with minimum-scope vault access (`Homelab` only). Stored as Forgejo secret |
| **Actions runner → Git** | Deploy key with push access to homelab repo. Read-only on all branches except `main` |
| **Homepage → internet** | Protected by Authentik Forward Auth. No unauthenticated access to service catalog |
| **Homepage → home server** | Health checks go through site-to-site WireGuard tunnel (encrypted, private) |
| **Renovate → Docker Hub** | Read-only registry access. No credentials needed for public images |
