## Why the patcher is dropped rather than re-anchored

Nothing in this repository can ever pass the option this patcher installs, so re-anchoring it would
buy a flag no arm renders:

* **rejected, with the measurement**: `docs/services-ai-rejected.md` — "`never-evict` prompt pin
  (`--never-evict-kv-cache-*`) | rejected | Zero blocks reserved; prefix caching already serves
  95.1 %"; the arms that carried a pin (`u4-pin`, `v16b-pin`) are recorded rejected in the same doc.
  Not re-decided here.
* **no reader**: `IaC/ansible/templates/docker_services/spark-ai/docker-compose.yml.j2:83` adds the
  `--never-evict-kv-cache-*` pair only `if profile.never_evict_prompt`, and every profile's value is
  the empty anchor `*nev` (`IaC/ansible/group_vars/spark.yml:356`) — `fast8` included, by the merge of
  `*u_x`. `scripts/bench/spark-llm-render-matrix.py` holds that as an assertion, and
  `scripts/gate/check_spark_llm_gate.py` keeps the pin-off invariant armed because a stray pair once
  crash-looped the engine (`reasoning` restarts=105).
* **capable-list gate**: `spark_llm_never_evict_capable_images: [ultrafast]` — the day-0 lineage only.
  An `ultrafast-v32` arm that ever set the prompt is refused by `roles/spark-llm-profile` and by the
  gate, so a future re-decide must change that list in review, not inherit a patcher by accident.
* **no build-time reader**: the staged tree has one mention of the flag outside the patcher, a comment
  in `src/patch_mamba_align_split.py`, and no `spark_profile_fast8_artifact_probes` entry names it.

`Dockerfile.v32` step 5 drops the patcher with the same shape of guard as step 12: it re-measures the
condition at every build — the `watermark=` line must still be the site, and the day-0 two-line
sequence must still be absent — so a drop cannot silently become a re-add, and a base that ever
restores the day-0 shape stops the build and makes the patcher a decision again.
