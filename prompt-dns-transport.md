## ⛔ Traps that cost a round

* **The runner carries `librouteros`.** It is installed on the runner, added to `bootstrap-runner.sh`, and the interpreter
  is pinned for the `network` group. Reads + the four probes that lie: [docs/deployment-ansible.md](docs/deployment-ansible.md)
  §Network devices (router / switch). A router failure is a device or reachability fact, never a missing module.
* **RouterOS 7 has no `domain=`** — `set … domain=` aborts the import. DHCP option 15 rides an `/ip dhcp-server option` row
  referenced by each server's `dhcp-option`, and the hex value must be written **inline** (`:local` + `value=$dom` reports
  success and writes nothing). Read back with `print detail` / `raw-value` or the `:foreach … get` form: a filtered print
  reports *unset* when the value **is** set.
* **The pin, not the prose:** the pinned headscale is what `headscale_version` in
  `IaC/ansible/group_vars/all/versions.yml` says, and rows and prose quote versions that drift. Re-read the pin before
  repeating a version or an exclusivity claim. Same rule for Technitium (`technitium_version`, same file), for the
  tailscale **client** whose code settles HD-435's answer (`tailscale_host_version`, same file — a bump is the moment a
  client-side "answers ONE A record" claim gets re-read rather than re-quoted), and for every image tag here.
* Split-horizon truth: **retirement is a ledger entry, not an absent flag** — `zone_kogler_si_retired` is what the seed's
  prune leg deletes from, and `sec.kogler.si` is its only entry; never infer retirement from `enabled:`. A `.ts` alias is
  not a retirement either: `dsh` answers nothing in any namespace and `pi-dev` survives ONLY as `pi-dev.ts.kogler.si`, a
  second name on the live oldsrv cockpit backend ([docs/network-vpn.md](docs/network-vpn.md) §Pattern B), while the PLAIN
  `pi-dev.kogler.si` publishes nothing by design. Likewise the orphan `localhost` headscale node is known residue, not drift.
* The seat constraint that came with the DNS-tier rulings: `pi-oldsrv.ts.kogler.si` is a headscale **MagicDNS `extra_record`**
  (`tailnet_ts_only_subdomains`), **not** a Technitium record — the seat must still load with Technitium **stopped**, and
  anything that changes the MagicDNS answer set belongs to HD-435's `zone_kogler_si` field, not to the resolver rows.
* `tailscale-node` wiring landmines: the role is wired into `home_servers.yml`, `raspberry_pi.yml` **and** `spark.yml`,
  each with an explicit `tags:` (a bare role carries none, so `--tags tailscale-node` is the join run) and opt-in by
  `tailscale_node_enabled`; the pinned `.deb` needs `dpkg --print-architecture`, not the kernel fact.
* Headscale answers and A records are different objects: `ha_vip` appears only in the `ha`/`dns-pi` **A records**, never as a
  client resolver address — that is HD-477's whole defect, so do not "fix" it by publishing the VIP as a record.
