## 0. How this backlog works

- **One row = one outcome.** New work gets `HD-<next>` and links its owning `docs/*.md`.
- **A row is not a changelog.** It says **what is still missing** and, usefully, **how to do it** — the command, the gotcha, the measurement you would otherwise re-take. Everything *durable* (a finding, a root cause, how a subsystem behaves, what was shipped and verified) goes into the owning `docs/*.md` and the commit, and the row keeps only a link to it. So a healthy edit that lands a discovery makes the row **shorter**, not longer, and a row whose `⏳` list is empty is deleted, not decorated with a ✅. Litmus test before saving: does this sentence help whoever finishes the task, or does it only describe what already happened? The first goes in the row, the second in the doc, and neither twice.
- **Priority (P):** 1 = highest (how hot), module = what domain it touches. Priority is per-row, modules group.
- **Executors:** `AI` · `AI + gate` (human checkpoint) · `AI + Human` (joint) · `Human` (blocks).
- **Lifecycle:** open → (decided) → done — ONE pattern (CONVENTIONS §4): a **fully-done** row is DELETED from this file (record lives in the owning doc + git history); an **IaC-done-but-deploy-gated** row STAYS with a `⏳` tail (trimmed to pending items) until the live verify closes it. Deferred → park section. **Decisions:** a decided item is written **once** to its owning `docs/*.md` (+ the `<domain>-rejected.md` log where applicable) and the full rationale is **removed** from `todo.md` — §1 shows only still-open decisions/purchases (compact pointer, no struck duplicate). Historical decisions + done rows live in the frozen `reports/changelog.md` (archive-only).
- **Conventions / onboarding:** consolidated rule index + 10-step service-onboarding checklist in [`CONVENTIONS.md`](CONVENTIONS.md).
- **Service stages:** service-onboarding rows (per-checklist tasks) carry **`Stage: N/10`** in the bold title = current Service-onboarding checklist step ([CONVENTIONS.md](CONVENTIONS.md) §5). `10/10` = deployed + verified; only then does a row close. Non-service tasks (network/fix/decision) carry no stage marker.
