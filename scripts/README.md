# scripts/ — Homelab automation, linters & renderers

> **Role:** Reference map for the scripts in this directory — validation gate, SSOT renderers,
> and small utilities. Read it to pick the right script for a task (or avoid re-implementing one).
> **Linked from:** `CONVENTIONS.md` (§8) · `docs/index.md` (Conventions) · `README.md`
> **Authoritative specs:** owning docs named inline per script — concrete values always live in IaC
> (`group_vars/*.yml`, `host_vars/*.yml`, `rack-connections.json`), never in a generated doc.

Every script here is part of one of three groups: **validation** (the fail-closed repo gate), **render** (IaC/SSOT → generated docs), or a **standalone utility**. The single entry point for validation is
[`validate-all.sh`](validate-all.sh). The single unified render entry is [`render_all.py`](render_all.py) — a pure-Python umbrella over the 5 generated-doc renders below, with **no Ansible / WSL / 1Password CLI dependency**.

## The tree — what lives where

Folders are named for the toolchain the scripts drive, not for the doc domain they serve —
`ansible/`, not `deployment/`. Two folders are not domains and are declared here rather than
guessed from the tree:

| Folder | Why it exists |
|---|---|
| `lib/` | Not runnable — the pieces the rest of the tree shares. Everything here exists to stop a second copy of one decision (where the repo root is, what a pin is, which planes a seat has) from becoming the fleet's second opinion. |
| `gate/` | The fail-closed repo gate. Its owning doc is CONVENTIONS.md, which is why it is a folder and not a domain: like CONVENTIONS itself it is cross-cutting and has no subject area. |
| `ansible/` | Everything that drives Ansible — the control node, the runner, and the renderers whose real producer is playbooks/render-docs.yml. |
| `secrets/` | The 1Password leg: provisioning, the bulk exporter the IaC pre-pass uses, and the key-injecting generators. |
| `git/` | A clone's git identity: the two bootstrappers and the unattended-identity payload they install. |
| `harness/` | The pi.dev seat family — the driver, the plane owners, the from-zero installers, and the specs they deploy. Fan-out is declared in lib/seat-planes.yml, never here. |
| `bench/` | Serving-leg instruments: what to measure, how to prove it, and the evidence it produced. The spark instruments came out of spark/ so one instrument has one home (artifacts included). |
| `hardware/` | Run-it-on-the-box collectors and the one-shot platform fixes. |
| `testdata/` | fixtures the gate feeds its own checkers — excluded from the registry below, because a tree of fakes is not a table of tools |

**The `gate/` and `lib/` exception, in prose (a docs/ reorganisation is open work, and this is deliberate).** `docs/` gets its own reorganisation and a `harness` domain decision in [[]] — same naming question one level up, ~2,289 `docs/<file>.md` references, its own owner gate. Those two folders' exception note lives HERE, in prose, precisely so  can change the domain set without touching a checker: nothing in `gate/check_script_layout.py` hardcodes a domain list, so the day the domain set moves, only this paragraph needs editing. Do not move that exception into the checker. The `harness` **doc** domain has since landed (`docs/harness.md`), and this folder keeps its name for the reason the table gives: it names the pi.dev toolchain its scripts drive. That the two words now coincide is a decision, not the taxonomy folding into the tree — a folder is a toolchain, a `domain:` is a placement axis, and `gate/` proves a folder need not answer to any domain at all.

Exit 0 · 1 boundary (no credential — a SKIP, never a green) · 3 the pipe rule refused a tty · 4 `--sdk-required` found no importable SDK. **Blind spots:** the batched read is per-PROCESS sharing (two legs in one run read once each — the account bucket buys the handful, and cross-leg RAM sharing inside one validate-all process is not what this is); the fallback costs what the batched path would have saved until the seat step lands; and the SDK path has never run against the live bucket here — this lane treated the account as unspent and tested every arm on fixtures and stubs, with the quota proof parked in the backlog's request-bucket row. | [`1password.md`](../docs/1password.md) §What a gate run costs the vault, `lib/vault-env.sh` (the credential rule it borrows) |

| [`check_todo_done.py`](gate/check_todo_done.py) | **`todo.md` done-row sweep + `prompt.md` handoff check** — flags todo rows marked DONE/LIVE or with a completion glyph that were **not deleted** (a fully-done row must be removed — record lives in owning docs + git; only deploy-gated rows with a real `⏳` tail stay). Also scans `prompt.md` (the next-session handoff): an HD presented as **open work** there whose todo row is gone (stale claim) or claimed **whole-row done** while todo still has it open (contradiction) → exit 1; sub-IDs inherit parent open-ness; phase-done prose on an open row is not a contradiction. **Duplicate-ID gate:** keys row ids on the NUMERIC STEM and exits 1 when one id heads more than one row, printing `todo.md:line:col` for each — two rows for one id can reach `main` through a merge that reports no conflict because they sit in different module sections. Stem-keying means a letter-suffixed row collides with its bare parent on purpose; a genuine sub-task pair is exempt via `SUBTASK_PAIRS`, which must carry its reason in the comment; the self-test asserts BOTH halves (an unregistered `<n>z` is flagged, a registered one is silenced) so the exemption cannot become an untested hole. `grep -o '^HD-[0-9]*' \| sort \| uniq -d` is NOT a substitute: truncating the id calls a legal `<n>a`/`<n>b` pair a duplicate and cannot see the real one. Re-run it immediately before committing AND again after any rebase over `todo.md`; when EDITING a row that might be duplicated, match on its SUBJECT TEXT, never `^HD-<n>` (a duplicate gives two hits). The canary mutates `todo.md` in-process and restores it from a byte snapshot in `finally`. Wired into `validate-all.sh` **by command, not by number** — that file's `--list` prints the live set and its header numbers are historical. **Marker grammar (self-tested):** a completion marker is a completion glyph or an **UPPERCASE** marker word at a word boundary — lowercase prose is not a claim (this used to be a case-insensitive substring test, so ordinary prose like "deliver the record" became completion claims). The row-level and prompt-level vocabularies are deliberately **not** identical (`REJECTED` beside an id does not mean the row is finished), and a done-claim is forgiven if the same HD is presented as open work anywhere else in `prompt.md`, which is what lets phase-done prose like "IaC merged ⏳ deploy" through. **Claim attribution is per-ENTRY, not per-window:** a marker counts for an id only when it sits in the SAME entry as that id — a bullet / numbered item / heading / table row plus its wrapped continuation lines — and, when one entry names two ids, in the nearer half of the gap between them (`_prompt_claim_spans`). `--self-test` pins the shapes AND the structural half — no claim region may cross its entry — so re-widening the window trips the invariant, not just one verdict. **Reference existence — `--refs`, its own gate item:** every `HD-<digits>` token named in ANY root `prompt*.md` brief must match a `^HD-<id>` row in `todo.md`, else FAIL naming `file:line`. ## Notes & conventions

- **A cross-platform leg asks the same question on every seat, because a different question reads as a verdict, not an error.**
  A two-word launcher (`py -3`) stays an argv array — quoted as one word it is a program called `py -3`, and rc 127 arrives
  where an invariant was supposed to be tested. A path is resolved only through a shell that can read it:
  [`lib/repo_root.py`](lib/repo_root.py) `hl_bash()` probes which `bash` sees the target, because a WSL bash cannot see
  `D:\…` and a Git bash cannot see `/home/…`, and a blind one reports the contents it could not see as absent. Interpreters
  are probed, not named: [`lib/python.sh`](lib/python.sh) `hl_python` refuses a Microsoft Store alias stub and a candidate
  that cannot import what the leg needs. A machine-readable pipe pins LF, since a Windows text-mode stream appends a
  carriage return to the last field — the one a bash comparison reads. And [`lib/python.sh`](lib/python.sh) exports
  `PYTHONUTF8=1` on a Windows seat, at the place the interpreter itself is decided: the pin belongs to the launcher rather
  than to the pool, so a leg a person runs straight from a prompt reads the same tree as the same leg run by
  `validate-all.sh`. git answers in UTF-8 while a native interpreter decodes `text=True` with the ANSI codepage, so a dead
  reader thread returns `stdout = None` and a gate's own crash reads as a finding about the tree.
- **A seal rewritten from a Windows seat is re-read on a Debian one.** `--reseal` writes its baseline through the seat's
  text mode, so on a Git-Bash seat the file can come out CRLF while `.gitattributes` pins the tree to LF. git normalises the
  committed copy and every reader tolerates both, so nothing breaks — but the seat that wrote a seal is not the seat that
  proves it, and a seal re-read where it was written proves only that both seats tolerate the same file.
- **A check that builds a git fixture scrubs the caller's git location.** `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`,
  `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR` and `GIT_SEPARATE_GITDIR` outrank both `git -C <dir>` and the child's working
  directory, so one inherited from a pool run writes the fixture's objects, refs and worktree registrations into the
  repository the gate is grading — the fixture then grades a tree it rewrote itself. Scrub them for the fixture's lifetime
  and prove the fixture owns its git-dir before it writes an object. Owning spec: `CONVENTIONS.md` §6.
- **An absent path can be an intentional absence — ask git, not the checkout.** `git check-ignore` is the authority on
  whether a missing generated file is a defect or renderer output, and it answers only for the spelling it is handed: a
  platform separator reads as an escape (so the answer for a path it does ignore comes back "not ignored"), and a
  directory-only pattern matches only a query that still carries the trailing slash. Ask in slashes, never normpath the
  query, and keep the comparison in one spelling — otherwise a lookup that is correct alone disappears inside a run on one
  seat, and the verdict describes the checkout rather than the tree.
- **Never edit a `-generated` doc directly** — change the SSOT (`group_vars/*.yml`, `rack-connections.json`) and re-render, then `git diff --exit-code` to confirm.
- **A script must not derive the repo root from its own depth — and a probe that cannot see the files must not be able to say OK.** Every script resolves the root by walking UP to the two structural markers (`IaC/ansible` + `docs/index.md`) via `lib/repo-root.sh` / `lib/repo_root.py`, and fails loud when nothing matches; every tree-walking checker asserts a non-empty corpus through `require_corpus()` (a walk that found nothing is a broken root, not a clean tree). `gate/check_script_layout.py` is the ratchet that keeps the fixed-depth derivations from regrowing.
- **`validate-all.sh` judges what is TRACKED — so `git add` a new file before believing a green run.** The path/secret/table walkers list files with `git ls-files`, so an untracked file is invisible to them. For a **new validator** the same trap is worse — a green run in which the new check never executed.
- **Layout:** the registry below is the tree — folder by folder, one row per tracked file under `scripts/` (`gate/check_script_layout.py` enforces registry ≡ tree). Top level holds the entry points only (`README.md`, `next-hd.sh`, `render_all.py`, `validate-all.sh`); everything else lives in its toolchain folder (`ansible/`, `bench/`, `gate/`, `git/`, `hardware/`, `harness/`, `lib/`, `secrets/`, `testdata/`). The agreed structure, the per-file assignment and the stage order are `prompt-scripts.md` / `todo.md`  — read that before proposing a move.
- **Judge `validate-all.sh` by its EXIT CODE, never by a filtered view of its output.** A pipeline's status is the last command's (grep exits 0 when it finds something), so a run that printed `FAIL: …` could happily commit and push. Run the gate, check `$?` (or `&&` on the bare command), and only then filter the log for reading.
- **No secrets outside 1Password `Homelab-ansible`.** Render scripts that need one (e.g. `render-routeros.yml` → device `.rsc`) resolve via `lookup(...)`; the pure-Python renderers here intentionally touch **no** secrets (they read only the YAML/JSON SSOT).
- **Windows vs Linux:** the Python scripts run cross-platform (PyYAML + Jinja2). Ansible playbooks (`render-docs.yml`, `render-routeros.yml`) require WSL/CI on this machine. The Debian/WSL ext4 primary is the canonical runner, so scripts must not assume Windows-only launchers/paths; the gate enforces this (§Portability). Like `ansible-run.sh`, the `validate-all.sh` `--syntax-check` gate exports `ANSIBLE_CONFIG`/`ANSIBLE_ROLES_PATH` from the repo root so roles resolve.
- **Live converges run ASYNC:** a full/`--tags docker_services` converge takes **10–30+ min** (Bulk 1P pre-pass, authentik glue, per-service compose up, restart guards, Technitium seed). Running it in the foreground lets an outer timeout kill it **mid-restart** and poison the next run's restart guard. Launch converges detached and poll — the exact commands and the `cd`-checkout trap are in `docs/deployment-ansible.md` §Running a converge; `--check` is the only safe foreground form (fast, read-only). If a converge is killed mid-restart, the fix is idempotent: re-run the same playbook (the restart-on-config-change guard restarts the stack cleanly once the sibling containers are up).
- **Scoped service deploys need BOTH tags:** `-e docker_services_scope=<svc>` alone does **not** deploy the service. The deploy-loop include carries `docker_services` alone and the tasks inside `deploy-service.yml` carry only the service tag, so under `--tags docker_services` the include opens the file and the children drop — a silent no-op that reports `changed=0/1, failed=0` while the rendered compose stays stale on the host; asking the service tag alone never even parses the file. Correct form: `--tags docker_services,<svc>` (the four include rules, measured, are in `docs/deployment-ansible.md` §Tags & surgical runs; `gate/check_tag_coverage.py` + `testdata/check_tag_coverage/run.sh` enforce the static half). When a scoped run looks suspiciously cheap, verify with `docker inspect` / the rendered file rather than trusting the RECAP. **A role-level tag already covers its tasks, so the pair is only owed by a BARE entry:** a `roles:` entry that carries `tags: [<role>]` (e.g. `tailscale-node` in `playbooks/home_servers.yml` / `playbooks/raspberry_pi.yml`) cascades into every task of that role, while a bare `- monitoring` entry (`playbooks/home_servers.yml`, `storage.yml`, `raspberry_pi.yml`, `spark.yml`) brings no tag at all and its tasks must name their own; and a NEW tag on a lockout-capable role must land in `homelab_guard_tags` AND that guard task's own `tags:` in `playbooks/tasks/self-converge-guard.yml` in the same change, or `scripts/gate/check_self_converge_guard.py` reddens — a filter that selects the role but not the guard is the self-converge lockout, not a narrower run.
- **Never run a `docker_services` converge with `--diff` (secret hygiene):** the 1P bulk pre-pass is `no_log`, but the **template diff of a rendered `docker-compose.yml` is not** — `--check --diff` printed live `LITELLM_MASTER_KEY` / `OPENROUTER_API_KEY` values onto stdout into the run log (CONVENTIONS §6: never print a secret VALUE). `--check` alone stays safe; the *diff* is what leaks. Verify renders from the template or diff the rendered host file with secret lines filtered; purge any log that caught values (`shred -u`) instead of grepping it.
- **A script is launched by its own interpreter — `python3` (here: `$PY`, so the venv guard applies) for `.py`, `bash` for `.sh`.** `bash scripts/gate/<name>.py` is NOT a syntax error, it is a hang: bash parses the Python as shell, and a `"""` docstring line becomes a quoted string whose quoting swallows the lines below it, whose words are then word-expanded into a command — argv can end up holding source text, so `ps` shows a process named for a line of the file at 0.0 % CPU, reading an stdin that never closes. It is harmless to data, invisible to `bash -n` (which parses and never executes), and it survives deleting its own script because an executable is held by inode, not by path. When interpreter or path comes from a variable, quote both: `"$PY" "$script"` — an unquoted expansion re-splits a path containing spaces. Rule text and the fuller trap list: `CONVENTIONS.md` §6.
- **Validator wiring:** anything added to `validate-all.sh` must be listed here; keep the comment block in `validate-all.sh` in sync. `gate/check_registry_prose.py` is wired in (run + `--self-test`) — it is the CONVENTIONS §6 state-only rule applied to this registry itself, and it refuses a walk that counts no rows.
- **Config / "what reads what":** `CONVENTIONS.md` §8 is the canonical index of rules these scripts enforce; this file is a *map* — the owning specs remain authoritative.

### Parallel 1Password operations — the concurrency contract ()

Three distinct mechanisms touch 1Password. They are NOT alternatives — they are a **pipeline across runtime layers**. Two of them parallelize a different direction each; the LiteLLM source glue is **serial** (its probe reads instructions via a `docker exec -i` heredoc that does not survive `xargs -P` — reverted , see the incident note below). They share one invariant: the **1Password rate-limit budget**. Keep them three; if a THIRD CONTROL/egress parallel loop ever appears, copy the bounded fan-out pattern below (not merge the scripts).

| Mechanism | Layer | Direction | Concurrency | Rate/limit knob | Purpose |
|---|---|---|---|---|---|
| bulk vault **read** (the exporter in `secrets/`) | **control-node**, `scripts/secrets/op-vault-export.py` (Python, `ThreadPoolExecutor`) | bulk **read** of static vault items into the `vault` dict | parallel per-item `op item get --reveal` | `op_vault_workers` (default 6) | /258 bulk pre-pass — ONE pass replaces ~160 per-template `op` lookups |
| `authentik-secret-egress.sh.j2` | **host** (bash, `xargs -P`) | **write** (sink): Authentik API → 1Password OIDC items | per-provider fetch+compare+write; **each worker owns a DISTINCT item** so parallel item-writes are safe | `OP_PARALLEL` (default 6) | /162 secret-egress OIDC cred seeding (write-only-if-changed) |
| `litellm-bootstrap-keys.sh.j2` | **host** (bash, **serial** — reverted ) | **read + mint** (source): 1Password → LiteLLM probe → mint back to 1Password | **SERIAL main loop** (`probe_key` reads its probe via a `docker exec -i` heredoc, which does not survive `xargs -P`; a parallel attempt failed live rc 3 and was reverted). mint/store serial (no alias race) | n/a (serial) |  LiteLLM scoped virtual-key bootstrap (vault-state-first) |

**The shared budget (persisted lesson,  15→6):** keep concurrent `op` calls ≤ **6 reads** (default), ≤ **4–6** when a run also mutates; only `curl`/`docker exec` HTTP **probes** may fan out wider. Never exceed this on a live converge — hosted 1P rate-limits can block for **15min+**.

**Extensibility rule:** to add a THIRD service/glue that touches 1Password, copy the fan-out harness (bounded `xargs -P "${OP_PARALLEL:-6}"`, `export -f <worker>`, worker writes an outcome **line** to a shared temp file, aggregate AFTER all workers finish — never read exit codes for the rc taxonomy, carry it in the lines). Do NOT extract a shared code file: these three render to self-contained `/usr/local/sbin/*.sh` on hosts where a lib dependency is a recovery risk, and each has a different write-concurrency/safety model. Duplication buys host-resilience; ossify the pattern HERE instead.

**⚠️ Incident note:** a parallel loop whose worker bodies **read stdin via heredoc into an external CLI** does NOT survive `xargs -P` fan-out. The LiteLLM glue's `probe_key` calls `docker exec -i ... <<'PYEOF'` (python reads instructions via stdin); under `xargs -P` the worker's stdin is a broken pipe, so the probe returns 000 / hangs → the glue failed rc 3 in the live converge (155s / 12 retries) and was **reverted to the serial loop** (the authentik glue, whose workers only `curl`+`op read` and never feed stdin, parallelizes cleanly: 21-22s → 11.94s). **Rule:** a fan-out worker may use `curl`/`op`/plain subprocess, but if its body pipes a heredoc into `docker exec -i`/`ssh`/etc, run that probe SERIALLY (or give it a stdin-neutral invocation). Confirm with `op service-account ratelimit` to identify a healthy `token read` budget (the current homelab SA sits at ~6 reads / 1000 well below the cap; the account `read_write` level was 230/1000 — the 15→6 lesson keeps us off that wall).
