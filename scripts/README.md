# scripts/ — Homelab automation, linters & renderers

> **Role:** Reference map for the scripts in this directory — validation gate, SSOT renderers,
> and small utilities. Read it to pick the right script for a task (or avoid re-implementing one).
> **Linked from:** `CONVENTIONS.md` (§8) · `docs/index.md` (Conventions) · `README.md`
> **Authoritative specs:** owning docs named inline per script — concrete values always live in IaC
> (`group_vars/*.yml`, `host_vars/*.yml`, `rack-connections.json`), never in a generated doc.

Every script here is part of one of three groups: **validation** (the fail-closed repo gate), **render** (IaC/SSOT → generated docs), or a **standalone utility**. The single entry point for validation is
[`validate-all.sh`](validate-all.sh). The single unified render entry is [`render_all.py`](render_all.py) — a pure-Python umbrella over the 5 generated-doc renders below, with **no Ansible / WSL / 1Password CLI dependency**.

## The tree — what lives where

Folders are named for the toolchain the scripts drive, not for the doc domain they serve —
`ansible/`, not `deployment/`. Two folders are not domains and are declared here rather than
guessed from the tree:

| Folder | Why it exists |
|---|---|
| `lib/` | Not runnable — the pieces the rest of the tree shares. Everything here exists to stop a second copy of one decision (where the repo root is, what a pin is, which planes a seat has) from becoming the fleet's second opinion. |
| `gate/` | The fail-closed repo gate. Its owning doc is CONVENTIONS.md, which is why it is a folder and not a domain: like CONVENTIONS itself it is cross-cutting and has no subject area. |
| `ansible/` | Everything that drives Ansible — the control node, the runner, and the renderers whose real producer is playbooks/render-docs.yml. |
| `secrets/` | The 1Password leg: provisioning, the bulk exporter the IaC pre-pass uses, and the key-injecting generators. |
| `git/` | A clone's git identity: the two bootstrappers and the unattended-identity payload they install. |
| `harness/` | The pi.dev seat family — the driver, the plane owners, the from-zero installers, and the specs they deploy. Fan-out is declared in lib/seat-planes.yml, never here. |
| `bench/` | Serving-leg instruments: what to measure, how to prove it, and the evidence it produced. The spark instruments came out of spark/ so one instrument has one home (artifacts included). |
| `hardware/` | Run-it-on-the-box collectors and the one-shot platform fixes. |
| `testdata/` | fixtures the gate feeds its own checkers — excluded from the registry below, because a tree of fakes is not a table of tools |

**The `gate/` and `lib/` exception, in prose (HD-1119 is open, and this is deliberate).** `docs/` gets its own reorganisation and a `harness` domain decision in [[HD-1119]] — same naming question one level up, ~2,289 `docs/<file>.md` references, its own owner gate. Those two folders' exception note lives HERE, in prose, precisely so HD-1119 can change the domain set without touching a checker: nothing in `gate/check_script_layout.py` hardcodes a domain list, so the day the domain set moves, only this paragraph needs editing. Do not move that exception into the checker. The `harness` **doc** domain has since landed (`docs/harness.md`), and this folder keeps its name for the reason the table gives: it names the pi.dev toolchain its scripts drive. That the two words now coincide is a decision, not the taxonomy folding into the tree — a folder is a toolchain, a `domain:` is a placement axis, and `gate/` proves a folder need not answer to any domain at all.

| [`lib/pi-seat.sh`](lib/pi-seat.sh) | **ONE `pin()` for the seat family (HD-1118 Stage 1)** — it was copy-pasted five times (`install-pi-debian.sh`, `pi-self-update.sh`, `install-nerd-font.sh`, `pi-settings-config.sh`, `install-pi-wsl.sh`) and every copy carried HD-1115's defect: `X="$(pin k)"` fetches in a **subshell**, where `exit 1` stops nothing, so on the three scripts with no `set -e` a missing pin continued with an empty value. ## Notes & conventions

- **Never edit a `-generated` doc directly** — change the SSOT (`group_vars/*.yml`, `rack-connections.json`) and re-render, then `git diff --exit-code` to confirm.
- **A script must not derive the repo root from its own depth — and a probe that cannot see the files must not be able to say OK.** Every script resolves the root by walking UP to the two structural markers (`IaC/ansible` + `docs/index.md`) via `lib/repo-root.sh` / `lib/repo_root.py`, and fails loud when nothing matches; every tree-walking checker asserts a non-empty corpus through `require_corpus()` (a walk that found nothing is a broken root, not a clean tree). `gate/check_script_layout.py` is the ratchet that keeps the fixed-depth derivations from regrowing.
- **`validate-all.sh` judges what is TRACKED — so `git add` a new file before believing a green run.** The path/secret/table walkers list files with `git ls-files`, so an untracked file is invisible to them. For a **new validator** the same trap is worse — a green run in which the new check never executed.
- **Layout:** the registry below is the tree — folder by folder, one row per tracked file under `scripts/` (`gate/check_script_layout.py` enforces registry ≡ tree). Top level holds the entry points only (`README.md`, `next-hd.sh`, `render_all.py`, `validate-all.sh`); everything else lives in its toolchain folder (`ansible/`, `bench/`, `gate/`, `git/`, `hardware/`, `harness/`, `lib/`, `secrets/`, `testdata/`). The agreed structure, the per-file assignment and the stage order are `prompt-scripts.md` / `todo.md` HD-1118 — read that before proposing a move.
- **Judge `validate-all.sh` by its EXIT CODE, never by a filtered view of its output.** A pipeline's status is the last command's (grep exits 0 when it finds something), so a run that printed `FAIL: …` could happily commit and push. Run the gate, check `$?` (or `&&` on the bare command), and only then filter the log for reading.
- **No secrets outside 1Password `Homelab-ansible`.** Render scripts that need one (e.g. `render-routeros.yml` → device `.rsc`) resolve via `lookup(...)`; the pure-Python renderers here intentionally touch **no** secrets (they read only the YAML/JSON SSOT).
- **Windows vs Linux:** the Python scripts run cross-platform (PyYAML + Jinja2). Ansible playbooks (`render-docs.yml`, `render-routeros.yml`) require WSL/CI on this machine. The Debian/WSL ext4 primary is the canonical runner, so scripts must not assume Windows-only launchers/paths; the gate enforces this (§Portability). Like `ansible-run.sh`, the `validate-all.sh` `--syntax-check` gate exports `ANSIBLE_CONFIG`/`ANSIBLE_ROLES_PATH` from the repo root so roles resolve.
- **Live converges run ASYNC:** a full/`--tags docker_services` converge takes **10–30+ min** (Bulk 1P pre-pass, authentik glue, per-service compose up, restart guards, Technitium seed). Running it in the foreground lets an outer timeout kill it **mid-restart** and poison the next run's restart guard. Launch converges detached and poll — the exact commands and the `cd`-checkout trap are in `docs/deployment-ansible.md` §Running a converge; `--check` is the only safe foreground form (fast, read-only). If a converge is killed mid-restart, the fix is idempotent: re-run the same playbook (the restart-on-config-change guard restarts the stack cleanly once the sibling containers are up).
- **Scoped service deploys need BOTH tags:** `-e docker_services_scope=<svc>` alone does **not** deploy the service. The deploy-loop include carries `docker_services` alone and the tasks inside `deploy-service.yml` carry only the service tag, so under `--tags docker_services` the include opens the file and the children drop — a silent no-op that reports `changed=0/1, failed=0` while the rendered compose stays stale on the host; asking the service tag alone never even parses the file. Correct form: `--tags docker_services,<svc>` (the four include rules, measured, are in `docs/deployment-ansible.md` §Tags & surgical runs; `gate/check_tag_coverage.py` + `testdata/check_tag_coverage/run.sh` enforce the static half). When a scoped run looks suspiciously cheap, verify with `docker inspect` / the rendered file rather than trusting the RECAP.
- **Never run a `docker_services` converge with `--diff` (secret hygiene):** the 1P bulk pre-pass is `no_log`, but the **template diff of a rendered `docker-compose.yml` is not** — `--check --diff` printed live `LITELLM_MASTER_KEY` / `OPENROUTER_API_KEY` values onto stdout into the run log (CONVENTIONS §6: never print a secret VALUE). `--check` alone stays safe; the *diff* is what leaks. Verify renders from the template or diff the rendered host file with secret lines filtered; purge any log that caught values (`shred -u`) instead of grepping it.
- **Validator wiring:** anything added to `validate-all.sh` must be listed here; keep the comment block in `validate-all.sh` in sync.
- **Config / "what reads what":** `CONVENTIONS.md` §8 is the canonical index of rules these scripts enforce; this file is a *map* — the owning specs remain authoritative.

### Parallel 1Password operations — the concurrency contract (HD-269)

Three distinct mechanisms touch 1Password. They are NOT alternatives — they are a **pipeline across runtime layers**. Two of them parallelize a different direction each; the LiteLLM source glue is **serial** (its probe reads instructions via a `docker exec -i` heredoc that does not survive `xargs -P` — reverted 2026-08-28, see the live lesson below). They share one invariant: the **1Password rate-limit budget**. Keep them three; if a THIRD CONTROL/egress parallel loop ever appears, copy the bounded fan-out pattern below (not merge the scripts).

| Mechanism | Layer | Direction | Concurrency | Rate/limit knob | Purpose |
|---|---|---|---|---|---|
| bulk vault **read** (the exporter in `secrets/`) | **control-node**, `scripts/secrets/op-vault-export.py` (Python, `ThreadPoolExecutor`) | bulk **read** of static vault items into the `vault` dict | parallel per-item `op item get --reveal` | `op_vault_workers` (default 6) | HD-257/258 bulk pre-pass — ONE pass replaces ~160 per-template `op` lookups |
| `authentik-secret-egress.sh.j2` | **host** (bash, `xargs -P`) | **write** (sink): Authentik API → 1Password OIDC items | per-provider fetch+compare+write; **each worker owns a DISTINCT item** so parallel item-writes are safe | `OP_PARALLEL` (default 6) | HD-146/162 secret-egress OIDC cred seeding (write-only-if-changed) |
| `litellm-bootstrap-keys.sh.j2` | **host** (bash, **serial** — reverted 2026-08-28) | **read + mint** (source): 1Password → LiteLLM probe → mint back to 1Password | **SERIAL main loop** (`probe_key` reads its probe via a `docker exec -i` heredoc, which does not survive `xargs -P`; a parallel attempt failed live rc 3 and was reverted). mint/store serial (no alias race) | n/a (serial) | HD-247 LiteLLM scoped virtual-key bootstrap (vault-state-first) |

**The shared budget (persisted lesson, HD-268 15→6):** keep concurrent `op` calls ≤ **6 reads** (default), ≤ **4–6** when a run also mutates; only `curl`/`docker exec` HTTP **probes** may fan out wider. Never exceed this on a live converge — hosted 1P rate-limits can block for **15min+**.

**Extensibility rule:** to add a THIRD service/glue that touches 1Password, copy the fan-out harness (bounded `xargs -P "${OP_PARALLEL:-6}"`, `export -f <worker>`, worker writes an outcome **line** to a shared temp file, aggregate AFTER all workers finish — never read exit codes for the rc taxonomy, carry it in the lines). Do NOT extract a shared code file: these three render to self-contained `/usr/local/sbin/*.sh` on hosts where a lib dependency is a recovery risk, and each has a different write-concurrency/safety model. Duplication buys host-resilience; ossify the pattern HERE instead.

**⚠️ Live lesson 2026-08-28 (HD-269 Step-1 re-baseline):** a parallel loop whose worker bodies **read stdin via heredoc into an external CLI** does NOT survive `xargs -P` fan-out. The LiteLLM glue's `probe_key` calls `docker exec -i ... <<'PYEOF'` (python reads instructions via stdin); under `xargs -P` the worker's stdin is a broken pipe, so the probe returns 000 / hangs → the glue failed rc 3 in the live converge (155s / 12 retries) and was **reverted to the serial loop** (the authentik glue, whose workers only `curl`+`op read` and never feed stdin, parallelizes cleanly: 21-22s → 11.94s). **Rule:** a fan-out worker may use `curl`/`op`/plain subprocess, but if its body pipes a heredoc into `docker exec -i`/`ssh`/etc, run that probe SERIALLY (or give it a stdin-neutral invocation). Confirm with `op service-account ratelimit` to identify a healthy `token read` budget (the current homelab SA sits at ~6 reads / 1000 well below the cap; the account `read_write` level was 230/1000 — the 15→6 lesson keeps us off that wall).
