# AI Stack — 1Password Items & OIDC Wiring (HD-105)

> **Role:** Deploy checklist — create the 1Password `Homelab` vault items + Authentik OIDC providers the
> AI stack compose templates reference (HD-100→HD-104) via fail-closed `lookup()`. Without these, every
> `docker compose up` for the AI stack aborts loudly (HD-65) — this checklist unblocks the whole stack.
> **Linked from:** `ai-stack.md`, `deployment-secrets.md`, `deployment.md`
> **Links to:** [`deployment-secrets.md`](deployment-secrets.md) (SSOT master list), [`ai-stack.md`](ai-stack.md)

> **Type map / field conventions** live in [`deployment-secrets.md`](deployment-secrets.md) §Type Map — one
> `<type>` per item, `_` is the only delimiter, **never** the field in the name, always pass `field=`.
> All items below are in the **`Homelab`** vault (the `op_vault` var) — no literal vault name in configs.

---

## 1. Items to create in 1Password (`Homelab` vault)

Create these **7** items. Each row gives the exact item name, the 1Password **item type**, the `field=` the
compose lookup reads, and who consumes it. **Fail-closed:** every one is required; none may be left as a
placeholder (a `default('')` is deliberately absent — HD-65).

| # | Item name | 1P type | fields set | Consumed by (compose) | Source of the value |
|---|-----------|---------|------------|------------------------|---------------------|
| 1 | `openrouter_api` | API Credential | `credential` = OpenRouter API key | LiteLLM (`OPENROUTER_API_KEY`) | OpenRouter account (paid LLM key) |
| 2 | `cohere_api` | API Credential | `credential` = Cohere API key | LiteLLM (`COHERE_API_KEY`) | Cohere account (embeddings key, embed-v4) |
| 3 | `litellm_master_key` | API Credential | `credential` = strong random token | Open WebUI (`OPENAI_API_KEY`) + OpenClaw → LiteLLM | Generate (`openssl rand -hex 32`) — shared auth token |
| 4 | `openwebui_secret` | Password | `password` = random secret | Open WebUI (`WEBUI_SECRET_KEY`) | Generate (`openssl rand -hex 32`) — session/encryption |
| 5 | `openwebui_api` | API Credential | `username` = OIDC client_id, `credential` = client_secret | Open WebUI (`OIDC_CLIENT_ID`/`OIDC_CLIENT_SECRET`) | **From the Authentik OIDC provider** (step 2 below) |
| 6 | `pgvector_db` | Database | `username` = DB user, `password` = DB password | PGVector (`POSTGRES_USER`/`POSTGRES_PASSWORD`) + db-backup DB04 | Choose a dedicated user for the RAG vector DB |
| 7 | `openclaw_gateway_token` | Password | `password` = gateway/Control-UI token | OpenClaw (`OPENCLAW_GATEWAY_TOKEN`) | Generated by `openclaw onboard` at deploy |

> **Docling (HD-103)** references no 1Password item — it has no API keys (models are public HF weights).

## 2. Authentik OIDC providers (create in the Authentik UI)

The two OIDC items are **not** random tokens — they are the **client credentials of Authentik OIDC provider
applications**. Create the provider first, then copy the client_id/secret into the 1Password items above.

### 2a. Open WebUI provider → `openwebui_api`
- **Provider type:** OIDC Provider.
- **Issuer / app slug:** `sso.kogler.si/application/o/openwebui/` (must match `OIDC_ISSUER` in `open-webui` compose).
- **Allowed redirect URI:** exactly `https://ai.kogler.si/oauth2/callback` (matches `OIDC_REDIRECT_URI`).
- **Scopes:** `openid profile email` (per-user chat/history isolation).
- **Client ID / Secret** → store in 1Password item **`openwebui_api`** (`username` = client_id, `credential` = client_secret).

### 2b. OpenClaw provider (deploy-time)
- Create an Authentik OIDC provider for OpenClaw's Control UI / gateway login; store its client creds in a
  dedicated `openclaw_api` item (same `matrix_api`-style pattern). Redirect URI per `openclaw onboard` output.

## 3. Post-creation wiring check

After items exist, confirm each compose renders (the fail-loud guard passes) and the endpoints are wired:

- [ ] `litellm` — `LITELLM_MASTER_KEY`, `OPENROUTER_API_KEY`, `COHERE_API_KEY` resolve; OpenAI-compatible endpoint responds on `services-internal:4000`.
- [ ] `open-webui` — `WEBUI_SECRET_KEY` + `openwebui_api` OIDC client resolve; `OPENAI_API_KEY` = `litellm_master_key`; OIDC login at `https://ai.kogler.si` works.
- [ ] `pgvector` — `pgvector_db` resolves; pgvector extension initializes; db-backup **DB04** dump of `pgvector` succeeds.
- [ ] `openclaw` — `openclaw_gateway_token` resolves; `openclaw onboard` generates a schema-valid `openclaw.json`; Open WebUI ↔ OpenClaw ↔ OpenCloud round-trip works.

---

## 4. Rollback / rotation notes

- **`litellm_master_key`** is shared by Open WebUI + OpenClaw — rotating it requires updating all three consumers, so treat it as a long-lived credential (rotate deliberately, not per-incident).
- **`openrouter_api` / `cohere_api`** are upstream keys only LiteLLM holds — rotate at the provider dashboard, then update the 1Password item; no compose change needed (LiteLLM reads via env).
- **OIDC client secrets** (`openwebui_api`) are rotated in Authentik; both provider and 1Password item must be updated together or the redirect/login breaks.
