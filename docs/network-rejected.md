| CAPsMAN per-MAC vlan-id access-list (HD-312 2b) | rejected | 2026-09-04 | **Not a capability of modern wifi-qcom-ac.** The HD-312 3-SSID rationale (2026-09-03) claimed `access-list` supports per-MAC vlan-id override (live-verified) — that capability belongs to the **legacy** `/interface wireless access-list` (`vlan-mode=use-tag` + `vlan-id` per rule). The **modern wifi** stack (`/interface wifi access-list`) cannot set a per-client vlan: the official MikroTik WiFi wiki (`vlan-id` property) states `802.11ac chipsets do not support this type of VLAN tagging, but they can be configured as VLAN access ports in bridge settings` — i.e. wifi-qcom-ac (the whole fleet, HD-232) does VLAN assignment only via the **CAP bridge access-port pvid model** (already live from HD-229/310), never a per-MAC override. Per-client VLAN isolation on wifi-qcom-ac is therefore not implementable; the per-device control that DOES exist is the **firewall MAC-address-list / `src-mac-address` forward-accept** model (iot-wan-allow, kids-* — HD-312 phase 3, live). The empty `routeros_capsman_access_list` SSOT/rsc scaffold drafted 2026-09-04 was reverted (would ship an inoperative `vlan-id` action). · [network-vlans.md](network-vlans.md) §3-SSID, [todo.md](../todo.md) HD-312 |
