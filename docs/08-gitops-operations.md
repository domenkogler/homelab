## Architecture Philosophy

- **Database-free, pure GitOps** — all config, versions, and documentation are plain text in Git
- **One Git repo** — IaC code + technical docs + family guides live together in the Forgejo repo
- **Doco-CD driven** — Docker deployments are fully automated via GitOps (Doco-CD watches repo, deploys on change). No manual workflow dispatch, no SSH for CD.
- **Ansible for OS bootstrap only** — system-level provisioning (Debian, Docker daemon, GPU) is one-time via Ansible. Application lifecycle is pure GitOps through Doco-CD.
- **Forgejo Actions for CI + VPS fallback** — Actions handles CI (tests, image scanning on PR) and serves as CD fallback for VPS deployments where Doco-CD cannot reach the Docker socket.

## Renovate Bot

Tracks upstream Docker image versions and enforces a stability delay before surfacing updates.

### How It Works
1. Renovate container runs on debhost, scans `docker-compose.yml` files in the repo
2. New upstream Docker image detected → **3-day hold** (stability delay)
3. After 3 days, update appears as a checkbox item on the **Dependency Dashboard** (a Forgejo Issue, auto-managed by Renovate)
4. Domen reviews the update, checks the box
5. Renovate generates a PR with the version bump
6. Merge PR → version string committed to Git → ready for deployment

### Configuration (`renovate.json` at repo root)

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "platform": "forgejo",
  "dependencyDashboard": true,
  "dependencyDashboardAutoclose": false,
  "dependencyDashboardTitle": "Homelab Dependency Dashboard",
  "packageRules": [
    {
      "matchDatasources": ["docker"],
      "stabilityDays": 3
    }
  ]
}
```

> The Dependency Dashboard is a **Forgejo Issue** (not a wiki page). Renovate creates and maintains it automatically. No manual setup beyond the config file.

## Doco-CD — GitOps Continuous Delivery (Primary CD)

Doco-CD is a lightweight GitOps CD tool that runs as a Docker container on debhost. It watches the homelab Git repository and automatically reconciles the Docker environment to match the desired state defined in docker-compose files.

### How It Works

1. Doco-CD runs on debhost, mounts `/var/run/docker.sock`
2. Monitors the Forgejo repo — **webhook** for instant deploy, or **poll** (every 3 min) as fallback
3. On change detection:
   - `git pull` latest commit
   - Resolves secrets from 1Password (external secrets provider) — never written to disk
   - `docker compose build` (if `build: true` for custom C# apps)
   - `docker compose up -d` (only changed services, not full stack)
   - Executes post-deploy hooks (regenerate Homepage config, update inventory docs)
4. Automatic drift correction — if a container is manually stopped or config changes, Doco-CD restores the Git-defined state on the next reconciliation

### Why Doco-CD for debhost

| Concern | Forgejo Actions + Ansible | Doco-CD |
|---------|--------------------------|---------|
| **Drift correction** | Manual (re-run playbook) | Automatic (every poll interval) |
| **Deploy speed** | Full Ansible run (SSH + task eval) | Docker compose only (seconds) |
| **Dependencies** | Actions runner, SSH keys, Ansible collections | Just Docker socket |
| **C# CI/CD** | Workflow dispatch or separate pipeline | `git push` → automatic build + deploy |
| **Secrets** | Ansible Vault or 1Password lookup | 1Password native SOPS integration |
| **Proxmox migration** | Needs runner VM/LXC | Same container, same config — portable |

### Container Setup (`docker-compose.doco-cd.yml`)

```yaml
services:
  doco-cd:
    image: ghcr.io/kimdre/doco-cd:latest
    container_name: doco-cd
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:80"        # Webhook endpoint (internal only, Traefik reverse-proxies if needed)
      - "127.0.0.1:9120:9120"      # Prometheus metrics
    environment:
      TZ: Europe/Ljubljana
      GIT_ACCESS_TOKEN: ${FORGEJO_TOKEN}
      WEBHOOK_SECRET: ${DOCO_CD_WEBHOOK_SECRET}
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - doco-data:/data
    cap_drop:
      - ALL
    healthcheck:
      test: ["CMD", "/doco-cd", "healthcheck"]
      start_period: 15s
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  doco-data:
```

### Deployment Config (`.doco-cd.yml` at repo root)

```yaml
name: debhost
compose_files:
  - docker/traefik/docker-compose.yml
```

### Execution Modes

| Mode | Trigger | Scope | Used For |
|------|---------|-------|----------|
| **Bootstrap** | Domen's laptop: `ansible-playbook bootstrap/site.yml` | Full OS provisioning (Debian, Docker, GPU, Doco-CD install) | Initial setup, disaster recovery |
| **Production** | Doco-CD: webhook (instant) or poll (3 min) | Docker container update (single or multiple) | Day-to-day: Renovate PR merge → auto-deploy |
| **Custom apps** | Doco-CD: webhook on push → `docker compose build` + `up` | Build + deploy in one step | C# app CI/CD — git push → deployed in <5 min |

## Forgejo Actions (CI + VPS Fallback CD)

Forgejo Actions remains available for **CI tasks** (testing, linting, image scanning on pull requests) and as a **secondary CD path** for scenarios where Doco-CD cannot reach the Docker socket (e.g., deploying to a remote VPS in Phase 2+).

### CI Pipeline (Primary Use)

```yaml
# .forgejo/workflows/ci.yml
name: CI — Build & Test

on:
  pull_request:

jobs:
  test:
    runs-on: docker
    steps:
      - uses: actions/checkout@v4
      - name: Build Docker image
        run: docker build -t my-app:${{ gitea.sha }} .
      - name: Run tests
        run: docker run --rm my-app:${{ gitea.sha }} dotnet test
      - name: Security scan
        run: trivy image my-app:${{ gitea.sha }}
```

### CD via Forgejo Actions (VPS Fallback, Phase 2+)

If services are split across debhost + VPS in Phase 2:

| Target | CD Tool | Why |
|--------|---------|-----|
| **debhost** (local Docker) | Doco-CD | Fast, drift-correcting, no SSH needed |
| **VPS** (remote Docker) | Forgejo Actions + Ansible | Doco-CD needs Docker socket access; SSH is the right tool for remote deployment |
| **HP Gen8** (no Docker) | Ansible (bootstrap only) | No CD needed — ZFS/NFS are system-level, configured once |

### Runner Prerequisites (for VPS CD path)

The Actions runner container needs:
- **SSH key** (ED25519) — access to remote VPS
- **1Password CLI** + `OP_SERVICE_ACCOUNT_TOKEN` — secret resolution at deploy time
- **Git push access** — to commit auto-generated docs back to the repo
- **Ansible collections** — `community.docker`, `community.general`

## Homepage (Family Launchpad)

A sleek, family-friendly web dashboard — the everyday landing page for all homelab services.

### Deployment
- **Runs on:** debhost Docker (services-internal network)
- **Exposed at:** `kogler.si` (root domain) via Traefik
- **Authentication:** Protected by **Authentik Forward Auth** via Traefik middleware. After first SSO login, session cookie persists — zero friction for family
- **Configuration:** `services.yaml` and `widgets.yaml` — auto-generated by Doco-CD post-deploy hook

### Health Checks
- **All services:** Monitored via local Docker socket (all containers co-located on debhost)
- **Status indicators:** Green/red dots on each service tile
- **Local-only links:** Services like Home Assistant (`ha.kogler.lan`) and Technitium (`dns.kogler.lan`) show as links but only resolve on home network or VPN

### Auto-Generation

After Doco-CD deploys or updates any container, the `.doco-cd.yml` post-deploy hook:
1. Renders `homepage_services.yaml.j2` → writes to `/opt/homepage/config/services.yaml` on debhost
2. Renders `homepage_widgets.yaml.j2` → writes to `/opt/homepage/config/widgets.yaml` on debhost
3. Reloads Homepage container
4. Commits both files to Git (so the repo reflects current state)

## Deployment Lifecycle (End-to-End)

### Upstream Images (Immich, Authentik, OpenCloud, ...)

```
Upstream Docker Release
        │
        ▼ (Renovate detects new version)
  3-Day Stability Hold
        │
        ▼
  Renovate posts to Forgejo Issue (Dependency Dashboard)
  □ immich: v1.120.0 → v1.122.1
        │
        ▼ (Domen checks the box)
  Renovate creates PR with version bump
        │
        ▼ (Domen reviews release notes, merges PR)
  Version committed to main branch
        │
        ▼ (Doco-CD detects new commit — webhook or poll)
  docker compose pull && docker compose up -d immich
        │
        ▼ (Doco-CD post_deploy hooks)
  ├─ Regenerate Homepage services.yaml (new version shown)
  ├─ Regenerate inventory docs
  └─ Commit + push updated docs to repo
        │
        ▼
  Homepage reloads → family sees updated status
```

### Custom C# Applications (Fast Lane)

```
git push → Doco-CD webhook → docker compose build + up → deployed in <5 min
```

### VPS Services (Phase 2+ Fallback)

```
Renovate PR merge → Forgejo Actions workflow_dispatch → Ansible → SSH → VPS Docker
```

## Security Boundaries

| Boundary | Detail |
|----------|--------|
| **Doco-CD → Docker socket** | Doco-CD mounts host Docker socket read-write. Runs as non-root container with `cap_drop: [ALL]`. Socket access is the only privilege |
| **Doco-CD → Forgejo** | Git access token (read-only on repo, webhook receive). Token stored as Doco-CD environment variable |
| **Doco-CD → 1Password** | Service Account token with minimum-scope vault access (`Homelab` only). Secrets resolved at deploy time, never written to disk |
| **Doco-CD → Git (post-deploy)** | Deploy key with push access for committing auto-generated docs (Homepage config, inventory) |
| **Actions runner → VPS (Phase 2+)** | Dedicated SSH key (separate from Domen's personal key). Key stored as Forgejo secret |
| **Actions runner → 1Password (Phase 2+)** | Service Account token with minimum-scope vault access. Stored as Forgejo secret |
| **Homepage → internet** | Protected by Authentik Forward Auth. No unauthenticated access to service catalog |
| **Renovate → Docker Hub** | Read-only registry access. No credentials needed for public images |
